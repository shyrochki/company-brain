# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Що це за репозиторій

Company Brain — єдине джерело правди компанії у форматі docs-as-code: Markdown у Git, рев'ю через Pull Request. Це база знань, а не кодова база, тому збірки, лінтера й тестів тут немає.

Інші інструменти (Slack, Notion, Drive, Gmail) живлять цей репозиторій, але саме він є джерелом правди. Якщо дані розходяться, правильним вважається записане тут; розбіжність варто показати людині, а не виправляти мовчки.

## Структура

- `docs/about-company.md` — компанія, продукт, позиціонування
- `docs/team.md` — ролі, обов'язки, онбординг новачків
- `docs/tools.md` — інструменти та адміни (облікові дані — в 1Password)
- `docs/runbooks/` — покрокові процедури: customer-onboarding, inbound-lead, support-escalation, billing, releases, hiring
- `docs/team-rules/` — правила команди: decisions, questions, customer-data, passwords, friday, language, claude
- `docs/info/` — довідкова інформація: out-of-office, kaffee-nord
- `README.md` — що це, як влаштовано, хто за що відповідає
- `CONTRIBUTING.md` — hard rules і як вносити зміни
- `maintaining.md` — хто підтримує Brain і як він лишається актуальним
- `GLOSSARY.md` — терміни й абревіатури
- `open-questions.md` — питання без відповіді
- `CODEOWNERS` — власники сторінок для рев'ю

## Правила

Перед будь-якою зміною прочитай `CONTRIBUTING.md` (повні правила) і `maintaining.md` (хто відповідає за Brain і як він підтримується) та дотримуйся їх.

### Відповіді на запитання про компанію

Спершу шукай відповідь у `docs/` (а також у `GLOSSARY.md`, якщо це доречно), і лише потім відповідай. Не вигадуй: якщо відповіді немає, прямо скажи про це. Посилайся на файл, з якого взято відповідь.

### Зміни

Нова інформація потрапляє сюди тільки через Pull Request, ніколи напряму в `main`.

Одна гілка — на одну логічну зміну, тобто на один PR. Якщо ти вже працюєш не в `main`, а в гілці для поточної задачі — продовжуй у ній. Нову гілку створюй лише від `main` і лише для нової, окремої задачі. Ніколи не створюй окремих папок чи worktree.

Якщо зміна додає, перейменовує або видаляє документ, у тому самому PR онови таблицю 'Start here' у README.md, щоб вона вказувала лише на файли, які існують.

У тому самому PR:

- онови "Last reviewed" на всіх змінених сторінках;
- якщо зміна додає сторінку або змінює її Owner/Backup, онови `CODEOWNERS`.

### Як писати сторінки

- Кожен новий файл починається із заголовка `# ...`, а одразу під ним іде блок: `Owner: … · Backup: … · Last reviewed: YYYY-MM-DD`.
- Використовуй лише факти, які дає людина. Нічого не вигадуй.
- Якщо для розділу немає фактів, пиши `_Буде заповнено._`.
- Невідоме записуй в `open-questions.md`.

### Що не можна додавати

У жодному файлі, прикладі чи повідомленні коміту не має бути:

- паролів, ключів доступу, API-ключів, токенів — лише вказуй, що вони в 1Password;
- контактних даних клієнтів (телефонів, email, адрес) — про клієнтів записуємо лише назву компанії-клієнта та ім'я контактної особи в цій компанії;
- фінансових деталей;
- дуже чутливих внутрішніх даних (наприклад, зарплат);
- особистих нотаток і рефлексій конкретної людини.

Якщо такі дані трапилися у матеріалі, який треба додати, не переноси їх і повідом про це людину.
